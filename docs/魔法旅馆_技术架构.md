# 魔法旅馆 — 技术架构设计文档

> 玩法以 [`魔法旅馆_Demo需求文档.md`](./魔法旅馆_Demo需求文档.md) 为准。  
> 本文只定：**怎么拆模块、数据怎么流、场景怎么挂、哪些东西允许做成 Manager**。  
> Demo 砍掉的系统（商店 / 装修 / 联机 / 永久成长）本文只留扩展接口，不进入当前迭代。

---

## 0. 技术栈与形态

| 项 | 选择 |
| --- | --- |
| 引擎 | Cocos Creator 3.8.x |
| 语言 | TypeScript |
| 类型 | 3D 单人厨房 / 魔法经营 / 轻模拟经营 |
| 分辨率 | 750×1334 竖屏锁定 |
| 镜头 | 斜俯视，玩家不能转视角、不捏合缩放 |
| 地图 | 3D 手工搭建（`game/prefab/LevelN`），不是程序化大地图 |
| 寻路 | **Grid + A\***（占格、堵路、魔石、AI 避让都走同一套格子） |
| 主场景 | **单一游戏主场景 `Battle`**：3D 地图 + UI 分层；`Start` 仅作启动 / Loading |

当前工程里已有 Recast 导航原型（`assets/script/navmesh`）。P0 可用它验证「点一下走过去」；**正轨实现以 Grid + A\* 替换**，避免 Recast 与台面占用、魔石堵路、伙伴让路各说各话。

---

## 1. 项目目标（工程视角）

玩家在限时班次里，于一间 3D 厨房中：

- 单击移动（无摇杆）
- 与设施交互（拿 / 放 / 加工 / 上菜 / 存钱）
- 获取食材、制作料理与药水
- 接收订单、服务顾客（入座 → 等待 → 用餐 → 付款）
- 贝壳必须再存入宝箱才计分
- 应付突发事件，夜晚做 3 选 1

Demo **不做**：商店、永久升级、装修、探索、联机。解锁下一班次只是流程进度，不是养成。

工程成功标准：

1. 班次逻辑能完全离开 UI 跑（无窗口也能模拟一局）。
2. 换关 = 换 Level 预设 + 换配置表，不改代码分支。
3. 新设施 / 新客人 / 新事件用 **组合组件 + 配置 + FSM 状态** 接入，不深继承。

---

## 2. 核心架构一句话

```
OOP Domain + EventBus + FSM + DataConfig + MVC(UI) + 少量 Manager + 组合优于继承
```

| 块 | 职责 | 不负责 |
| --- | --- | --- |
| **Domain** | 客人、角色、台子、物品栈、订单、班次规则 | 不直接操作 UI 节点 |
| **EventBus** | 跨模块通知（上菜成功、事件预兆、倒计时、入箱） | 不当成远程函数调用、不传巨大对象来回改 |
| **FSM** | 玩家指令、客人生命周期、加工台、神偷/鸟 | 不把整局游戏做成一个超级状态机 |
| **DataConfig** | 物品、配方、关卡时间轴、星级、夜抉择 | 不放运行时血量/手里拿什么 |
| **MVC(UI)** | 窗口、HUD、气泡、底栏按钮 | 不算分、不寻路 |
| **Manager** | 资源、UI 栈、音频、配置、对象池、班次编排 | 不写「GameManager 里什么都有」 |

## 3. 场景结构（单一主场景）

```
Start.scene          启动：框架 init → Loading → 打开 StartWnd
                         ↓ 仅切一次
Battle.scene         【唯一游戏主场景，班次中不销毁】
  ├─ Main Camera     斜俯视；班次 2/3 跟随玩家，限速
  ├─ Main Light
  ├─ MapRoot         BattleMapRoot：instantiate LevelN
  │    └─ LevelN     手工 3D 房间（墙/地/台/门）
  │         └─ NavBake / Grid 占格节点
  └─ Canvas / UIRoot BattleUIRoot → UILayerRoot 分层
       ├─ SceneUI    世界气泡、屏边感叹号（可挂 3D 跟随）
       ├─ MainWin    BattleWnd（倒计时、贝壳、暂停）
       ├─ Popup      夜抉择、结算、暂停菜单
       ├─ TopPopup   确认框
       └─ TipsGuide  引导、飘字
```

菜单、选关、夜抉择、胜负都是 **窗口**，不要再切 3D 场景。  
换班次：`BattleMapRoot.loadLevel(id)` 换掉 MapRoot 子节点 + `ShiftController` 读新表重置 Domain。

`Start.scene` 只解决：引擎起来、分包、进主场景。进过 Battle 之后，回菜单 = 关战斗窗口 / 清 Domain，**不卸载 Battle 3D**（若内存紧张，可销毁 Level 节点保留场景壳）。

## 4. 分层（从上到下）

```
┌─────────────────────────────────────┐
│  View（Cocos 节点 / Prefab / 窗口）   │  只表现、收输入、发 UI 事件
├─────────────────────────────────────┤
│  Presentation / Adapter             │  把点击打成 Command；把 Domain 打成 HUD 数据
├─────────────────────────────────────┤
│  Application（Shift / Command）     │  一局班次编排、单击命令、默认动作表
├─────────────────────────────────────┤
│  Domain（纯逻辑对象 + FSM）          │  可单测：订单、配方、耐心、优先级
├─────────────────────────────────────┤
│  Infrastructure                     │  GridPath, Resource, Config, Audio, Pool, EventBus
└─────────────────────────────────────┘
```

依赖方向 **只允许向下**。Domain 禁止 `import` UI 窗口类。View 禁止直接改 `Guest.patience`。

---

## 5. 组合优于继承

禁止：`SteakStation extends CookStation extends Interactable extends Actor` 这种四级继承。

推荐：一个场景物体 = **一个 Entity（Node）+ 若干组件**：

| 组件 | 用途 |
| --- | --- |
| `GridAgent` | 占格、寻路、移动 |
| `HandInventory` | 一种物品 + 数量（上限 3） |
| `Interactable` | 热区、到达距离 1.2m、选中描边 |
| `StationSlot` | 台上一种物品 + 数量；禁止交换 |
| `Processor` | 砧板/炉/锅/坩埚计时、焦糊 |
| `OrderBoard` | 客人订单、耐心 |
| `ClickTarget` | 单击 / 长按落到谁身上 |

玩家、伙伴共享 `GridAgent + HandInventory`；伙伴再挂 `PartnerBrain`（优先级表）。  
客人挂 `GridAgent + OrderBoard + GuestFsm`。  
工作台挂 `Interactable + StationSlot`，需要加工再加 `Processor`。

新设施 = 新组件组合 + 配置里的 `stationType`，不新增基类。

## 6. Domain 对象（OOP）

全部放 `assets/game/script/domain/`，尽量不持有 `Node`（需要世界坐标时持 `entityId`，由 View 同步）。

| 对象 | 职责 |
| --- | --- |
| `ItemStack` | `{ itemId, count }`，同 id 可叠，不同 id 不可共槽 |
| `Actor` | 玩家或伙伴：手、当前指令、药剂效果、移速 |
| `Guest` | 入座、订单、耐心、害羞/评委规则、离店 |
| `Station` | 类型（材料/放置/加工/餐桌/宝箱/垃圾桶/药桶/魔石） |
| `Order` | 订单 id、要提交的 item、贝壳基础价、评委是否分两道 |
| `Shift` | 倒计时、已入箱贝壳、愤怒数、星、时间轴游标 |
| `EventInstance` | 神偷/堵路魔/鸟的运行时实例 |
| `Command` | 单击产生的「对谁、到达后做什么」 |

配方、默认动作、AI 优先级是 **纯函数 / 表驱动**，不要写进某个巨大 `Game` 类。

```
ItemId  → items.json
Recipe  → recipes.json      // 切/烤/汤/兑/浇
Action  → DefaultAction.resolve(hand, station) → Place | Take | Process | Serve | None
```

## 7. FSM（只给复杂对象）

用轻量状态机（可自研 50 行：`enter/exit/update/event`），不要上通用行为树。

### 7.1 玩家 / 伙伴指令（Command FSM）

```
Idle → MoveTo(target) → Arrive → DoDefaultAction → Idle
                 ↘ Cancel（点自己 / 新单击覆盖）
长按满圈：Discard | SmashRock | Drink   （独立于单击指令，可在 Arrive 后触发）
```

新单击 **立刻覆盖** 旧指令（需求 3.4）。从单击到迈步 ≤ 0.1s：`CommandService` 同步改目标，寻路下一帧起步。

### 7.2 客人

```
SpawnAtDoor → WalkToSeat → Sit → ShowOrder → Wait
Wait → Served → PayShells → Leave
Wait → AngryLeave
Wait(害羞) → NeedCharm → Revealed → Wait
```

### 7.3 加工台

```
Empty → Processing → Ready → Empty
Ready 再计时 → Burnt（仅炉灶）
```

### 7.4 神偷（示例）

```
Warn → Enter → RushChest → Loot(1.5s 可打断) → Escape | Defeated
```

FSM 状态里只改 Domain；播动画、出警告条通过 EventBus。

## 8. EventBus

沿用现有 `EventManager` + `GameEvent` 枚举。班次相关事件集中新增，旧的挖地/连通事件逐步废弃，不要混用。

建议事件（示意）：

| 事件 | 谁发 | 谁听 |
| --- | --- | --- |
| `SHIFT_START / SHIFT_END` | ShiftController | UI、音频、AI |
| `COMMAND_ISSUED` | InputAdapter | 描边、起步音 |
| `ITEM_HELD_CHANGED` | Actor | 身前持有物、底栏喝药/投掷 |
| `ORDER_SHOWN` | Guest | 世界气泡 |
| `GUEST_ANGRY` | Guest | HUD、评分 |
| `SHELL_SPAWNED / SHELL_BANKED` | Table / Chest | 分数、伙伴 P1 |
| `EVENT_WARN / EVENT_FAIL` | EventDirector | 警告条、感叹号、SFX |
| `POTION_EFFECT` | Actor | 光圈 |
| `NIGHT_CARD_CHOSEN` | NightWnd | 下一班修正 |

约定：

- 监听方在 `BaseComponent.onDestroy` 已有 `offAllByTarget`，Domain 非组件对象要自己 `off`。
- **禁止** EventBus 上传 `Node` 去让逻辑 `getChild`。传 `id`。
- 同一帧不要用事件再改出发者正在遍历的列表（先拷贝再 emit，现有实现已拷贝）。

## 9. DataConfig

静态数据全部进 `table` 分包 JSON，经现有 `ConfigManager` 读取。禁止在代码里写死班次时间轴。

| 表 | 内容 |
| --- | --- |
| `items.json` | id、叠加上限、是否药水、显示色 |
| `recipes.json` | 设施类型、输入、时间、输出、能否焦 |
| `orders.json` | 订单、价格、出现班次 |
| `stations.json` | 台类型、默认动作、是否放置台 |
| `shifts.json` | 时长、Level 预设路径、客人时间轴、事件时间轴、星级线、AI 是否开放 P3 |
| `night_cards.json` | 三张抉择效果 |
| `ai_priority.json` | P0–P3 任务合法条件与倾向权重 |

关卡 **几何** 在 `LevelN.prefab`；关卡 **节奏** 在 `shifts.json`。  
预制体上的台子用组件或命名约定绑定 `stationId`，开局扫描 MapRoot 注册到 `StationRegistry`。

## 10. MVC（仅 UI）

```
View     BaseWindow / BattleWnd / NightWnd / WinWnd
         只绑按钮、进度条、列表

Presenter / Window 脚本
         听 EventBus、读 Shift 只读快照、调用 Application API
         不写配方、不寻路

Model    Domain + ConfigManager（UI 不持有第二份「战斗数值」）
```

现有 `UIManager` + `BaseWindow` + `UILayerType` 继续用。

| 窗口 | 层 | 说明 |
| --- | --- | --- |
| StartWnd / SelectWnd | MAIN_WIN | 可在进 Battle 前打开；进主场景后也可叠在 Battle 上 |
| LoadingWnd | 主包 | 只负责分包进度 |
| BattleWnd | MAIN_WIN | 倒计时、入箱贝壳、暂停；底栏情境按钮 |
| NightWnd | POPUP | 3 选 1 |
| WinWnd / LoseWnd / 终局 | TOP_POPUP | 星、再来一次 |
| ConfirmWnd / TipWnd | TOP / TIPS | 通用 |

世界空间订单气泡、选中描边、屏边感叹号：**SceneUI 或 3D 跟随节点**，不要全部做在 BattleWnd 里，否则会被底栏挡住或跟丢镜头。

## 11. 少量 Manager（白名单）

只允许这些全局单例（已有的继续用）：

| Manager | 职责 |
| --- | --- |
| `ResourceManager` | Bundle / Prefab / 音效；game 分包按目录加载，禁止全量 `preloadDir("")` |
| `UIManager` | 开窗关窗、缓存 |
| `ConfigManager` | JSON 表 |
| `EventManager` | EventBus |
| `AudioPlayer` | BGM/SFX |
| `PoolManager` | 气泡、贝壳、飘字 |
| `ShiftController` | **一局班次的编排入口**（唯一允许的「局内导演」，仍不是上帝类） |

**不要**再增加 `GuestManager`、`ItemManager`、`StationManager`、`AIManager` 这种按名词复制的 Manager。  
改用：

- `StationRegistry`（普通对象，班次开始扫描、结束清空）
- `GuestSpawner`（读时间轴 new Guest）
- `PartnerBrain`（挂在伙伴 Entity 上）
- `CommandService`（单击 → Command）

`ShiftController` 允许做的事：开局、读表刷客、刷事件、到点结算、通知换 Level。  
不允许：在里面写 A\*、写兑药公式、直接 `find("炉灶")`。

## 12. Grid + A\*

### 12.1 格子

- 世界 XZ 投影到整数格。建议 **0.5m / 格**（房间约 8×12m → 16×24 格，足够绕台）。
- 每格：`Walkable | Blocked | StationOccupant | Magstone | EventBlocker`
- 角色占 1 格；台子按 AABB 标 Blocked，交互点另存 `interactCell`（台前一格）。
- 单击空地：点到的地面格为终点。单击台子：终点 = 该台 `interactCell`。

### 12.2 A\*

- 四方向或八方向（厨房建议四方向，减少斜穿桌角）。
- 代价：直线 10，可加「远离玩家」轻微惩罚给伙伴让路。
- 魔石 / 堵路魔所在格不可走；砸开或击败后 `MAP_CELL_CHANGED`，正在寻路的 Agent 下一帧重寻。
- 寻路失败：玩家停在障碍前目标闪红；伙伴放弃该任务 2s（需求 8.4）。

### 12.3 与 3D 预设的关系

`LevelN` 摆好后，启动时：

1. 收集带碰撞的 Mesh / 盒体 → 标记 Blocked。
2. 收集 `Interactable` → 算 interactCell。
3. 门口、待命点、宝箱从命名节点或组件读取。

不在运行时每帧 raycast 整屋。NavBake / Recast 仅作对照，不作为占格真相。

## 13. 输入与默认动作（Application）

竖屏可玩区射线 → `ClickPicker`（热区比模型大 0.4m，重叠取近且朝镜头）。

```
PointerDown
  ├─ HUD / 底栏     → UI 自己处理，不选场景
  ├─ 长按计时 0.28s → 满圈才 Discard / Smash / Drink
  └─ 单击           → CommandService.issue(actor, target)
```

`DefaultAction.resolve(hand, target)` 严格按需求 3.4 / 3.5 一张表实现，单测覆盖：

- 空手 + 有货放置台 → Take
- 有物 + 空放置台 → Place
- 不同物 → WalkOnly + 提示「不能交换」
- 同物 → Stack（上限 3）
- 合法原料 + 空加工台 → PlaceOne + StartProcess
- 客人要的菜 → Serve
- 贝壳 + 宝箱 → Bank
- 空地 → MoveOnly
- 点自己 → Cancel

长按 **不** 走这张表的拿放。垃圾桶单击 = 只寻路。

PC 预览：左键单击、按住=长按、右键投掷、Q 喝药、Esc 暂停。

## 14. 班次循环

```
ShiftController.start(shiftId)
  → BattleMapRoot.loadLevel(config.levelPrefab)
  → 重建 Grid、注册 Station
  → 应用夜抉择修正（移速 / 开场药水 / 耐心或跳舞）
  → 生成玩家 + 伙伴
  → 时间轴：GuestSpawner、EventDirector
  → 每帧：Agent 移动、Processor 计时、Guest 耐心、PartnerBrain 0.3s 决策
  → 时间到 → 算星 → NightWnd 或终局
```

评分只读 **已入箱贝壳 + 愤怒数 + 评委是否成功**（需求第 10 节）。

---

## 15. AI 伙伴

`PartnerBrain` 每 0.3s：

1. 若当前任务仍合法且没有更高优先级 → 不换。
2. 否则按 P0→P3 表找第一条合法任务（需求 8.3）。
3. 倾向只改权重，关不掉 P0。
4. 玩家 `Command.targetId` 锁定的对象：伙伴跳过。
5. 输出也是 `Command`，与玩家走同一套 MoveTo + DefaultAction。
6. 不喝药、不砸石、不读心。

伙伴是 Domain + 组件，不是 `AIManager`。

## 17. 关键数据流

### 17.1 单击上菜

```
Battle 可玩区点击
  → ClickPicker 命中 Guest
  → CommandService.issue(player, guest)
  → A* 到 interactCell
  → Arrive → DefaultAction.Serve
  → GuestFsm.Served → 桌上 ItemStack(shell)
  → Event: SHELL_SPAWNED
  → 玩家再点贝壳 / 伙伴 P1 收起 → 点宝箱 Bank
  → Shift.banked += n
  → Event: SHELL_BANKED → BattleWnd 刷新
```

### 17.2 换班次

```
结算关闭
  → NightWnd 选卡 → 写入 BattleContext.nextModifiers
  → ShiftController.start(nextId)
  → MapRoot 换 Level 预设
  → Grid 重建、Registry 清空重扫
```
